## Held for Jack

- **B5 overlapping reschedules (and turning check-ins off mid-pass).** UNVERIFIED, and no headless test can settle it on `435e866`: the simulator test host cannot be authorised, so the center accepts no requests and stale slots can never be observed (the review's rerun hit the same wall), and `NotificationService` has no seam for a fake center. If real it self-heals on the next foreground. What would settle it: a device run that taps the End stepper from 21 to 20 at 15 minutes (Start 6) quickly, then logs the pending `posture.reminder.*` ids, or approval to add a center seam so a fake whose `add` suspends can prove it. The reverted fix (`f1526ae`, a `SerialTaskQueue` around every pass) is ready to cherry-pick. Decision: settle it on a device, or accept the fix as a precaution?
- **B8 first spent save comes back the next day.** The review calls it a product call ("Decide the rule rather than treat it as a defect"), and the fix takes a save away from users. Decision: should the weekly refill clock start when the streak starts (stamp `lastFreezeRefill` when `StreakState` is created, so the first spent save waits up to a week), or stay as shipped (the first spend refills on the next record, and the existing `testRefillWhenEmptyAndNoRefillDateSetsTo2` keeps pinning it)?
- **P6 Posture+ tab removed while selected.** The review leaves it unsettled: SwiftUI's handling of a `selectedTab` with no matching tag needs a simulator or device run, and reaching it needs a purchase, which a headless test cannot make. What would settle it: a sandbox purchase from the Posture+ tab on a simulator, then a screenshot of the tab bar. The reverted fix (`e9f867c`, reset the selection to Today when Pro turns on with tag 3 selected) is ready to cherry-pick. Decision: settle it with a sandbox run, or take the reset as a precaution?
- **P4 messaging.** Recovery now routes to calibration, but the user is still not told that their history was moved to a backup, and nothing can restore it. Decision: show a one-time notice after a recovery, and should there be a way to restore the backup?

Out of scope, noted for the same pass: P5 (a notification tap while a practice or walk is on screen; unsettled, needs one device run to see whether a root cover presents over Today's session cover) and P8 (a pending purchase shows no message in `OnboardingTrialView` and Settings' sheet; the review agrees it is a product call, and it touches the trial flow and paywall).
